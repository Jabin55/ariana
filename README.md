# 정치쌤 챗봇 · 실시간 수업

> 🎥 **실시간 온라인 수업 플랫폼**은 아래 [실시간 수업](#실시간-수업-live) 부분을 보세요.

고등학교 **정치** 과목(2022 개정 교육과정)을 공부하는 학생이 질문하고 답변을 받는 웹 챗봇입니다. Claude API를 사용합니다.

- **개념 질의응답**: 교과 개념을 학생 눈높이로 설명하고 헷갈리기 쉬운 점을 짚어 줍니다.
- **문제 풀이·퀴즈**: "문제 내 줘"라고 하면 OX·5지선다·서술형 문제를 내고, 학생 답을 채점·해설합니다.
- **정치적 중립**: 특정 정당·후보를 지지하지 않고, 쟁점은 여러 입장을 균형 있게 소개합니다.

## 실행 방법

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
export ANTHROPIC_API_KEY=sk-ant-...      # Anthropic 콘솔에서 발급
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

브라우저에서 http://localhost:8000 을 열면 됩니다. 같은 네트워크의 학생들은 `http://<이 컴퓨터 IP>:8000` 으로 접속할 수 있습니다.

## 인터넷에 배포하기 (Render)

이 저장소에는 [Render](https://render.com) 배포 설정(`render.yaml`)이 들어 있습니다.

1. Render에 GitHub 계정으로 가입·로그인합니다.
2. **New → Blueprint** 를 누르고 `jabin55/ariana` 저장소를 선택합니다.
3. `ANTHROPIC_API_KEY` 입력란에 API 키를 넣고 **Apply** 를 누릅니다.
4. 몇 분 뒤 `https://politics-chatbot-xxxx.onrender.com` 같은 주소가 생깁니다. 이 주소를 학생들에게 알려 주면 됩니다.

> 이 설정 파일(`render.yaml`)은 사이트를 **두 개** 만듭니다. 정치쌤 챗봇(`politics-chatbot-….onrender.com`)과
> 실시간 수업(`live-class-….onrender.com`)입니다. **실시간 수업은 Render 대신 해외 서버 한 대에 화상 서버와 함께 설치하는 것을 권장합니다** — 아래 [실시간 수업](#실시간-수업-live)의 설정 순서를 보세요. 그렇게 하면 Render의 `live-class` 서비스는 지워도 됩니다.
> 주소 앞부분은 서비스 이름으로 정해지니, 원하는 이름이 있으면 `render.yaml` 의 `name` 을 바꾸거나 Render 화면에서 바꾸면 됩니다.

이후 GitHub 저장소에 코드를 올리면 Render가 자동으로 다시 배포합니다.
무료 요금제는 한동안 접속이 없으면 잠들었다가, 다음 접속 때 깨어나느라 첫 화면이 30초~1분 정도 늦게 뜰 수 있습니다.

## 구성

| 파일 | 역할 |
|---|---|
| `app/prompts.py` | 챗봇의 성격·교과 범위·중립 원칙을 정한 시스템 프롬프트. **수업에 맞게 고치려면 이 파일을 수정하세요.** |
| `app/main.py` | FastAPI 서버. `/api/chat` 에서 Claude 응답을 스트리밍합니다. |
| `static/` | 채팅 화면(HTML/CSS/JS) |

## 설정 (환경 변수)

| 변수 | 기본값 | 설명 |

| `CHATBOT_MODEL` | `claude-haiku-5-5` | 사용할 모델 (기본: 가장 저렴한 모델) |
| `CHATBOT_EFFORT` | `low` | 답변 깊이(`low`/`medium`/`high`). 높을수록 느리고 비용이 늘어납니다. |

## 참고

- 대화 기록은 학생 브라우저에만 있고 서버에 저장하지 않습니다. 새로고침하면 사라집니다.
- 정책상 답변이 거절되면 서버에서 다른 모델로 자동 재시도합니다(`fallbacks: "default"`).
- 화면의 마크다운 렌더링 라이브러리(marked, DOMPurify)는 `static/vendor/`에 포함되어 있어 학교망에서 CDN이 막혀도 동작합니다.
- 시스템 프롬프트는 프롬프트 캐싱을 적용해 반복 요청 비용을 줄입니다.
- 학생들에게 공개 배포하려면 로그인이나 접속 제한, 사용량 제한(rate limit)을 추가하는 것을 권장합니다. 현재는 누구나 접속하면 API 비용이 발생합니다.

## 실시간 수업 (`/live`)

같은 서버에 들어 있는 **화상 수업 플랫폼**입니다. 중·고등학생 한 반(~35명) 규모를 기준으로 만들었고,
**학교에서 받은 구글 계정으로만 로그인**합니다.

| 기능 | 내용 |
|---|---|
| **강좌·수강신청** | 학기 초 선생님이 강좌(강의명·강사명·거점학교명·강의기간)를 개설하고 학생이 수강신청(거점학교 공동교육과정처럼 **다른 학교 학생도** 가능, 강의기간이 지나면 신규 신청 마감) → 선생님이 승인. 승인된 학생은 수업 때 **코드 없이** 첫 화면에서 바로 입장, 승인 안 된 학생은 코드를 알아도 입장 불가. 출결의 '미접속'도 수강생 기준 |
| 로그인 | 학교 구글 계정(정한 도메인)만 로그인. 처음 한 번 학교·학년·반·번호·이름 입력 → 학번 자동(예: 20315). 비밀번호를 저장하지 않음 |
| 화상·음성 | 선생님 카메라·화면 공유를 크게, 학생들은 작은 타일로. 휴대폰·크롬북에서도 동작 |
| 수업 진행 | OX·객관식·투표·주관식을 보내면 응답이 실시간으로 모이고(선택지별 인원·비율, 누가 무엇을 골랐는지), 원할 때 학생에게 결과 공개 |
| **자료 발표(PDF)** | 📄 PDF를 올리면 학생 화면에는 **자료만 크게** 보임(선생님 목소리는 계속, 영상은 받지 않아 데이터 절약). 선생님이 쪽을 넘기면 학생 화면도 함께 넘어감(← → 키). 선생님 화면은 '학생 영상 보기'로 학생 영상을 함께 보거나 숨김. PowerPoint는 PDF로 저장해서 올림(애니메이션이 필요하면 화면 공유). 자료는 '지난 수업 자료'로 남음 |
| **판서·화이트보드** | 자료 위나 빈 화이트보드(여러 쪽)에 펜 4색·형광펜·지우개·되돌리기·모두 지우기. 쪽마다 판서가 따로 남고, 학생 화면에 실시간으로 그려짐 |
| **과제** | 강좌 카드의 **📝 과제**에서 과제(제목·안내·마감·지각 제출 받기)를 내면 수강생 첫 화면 '📝 과제'에 D-day와 함께 보임. 학생은 파일(5개, 하나 20MB까지)·글로 제출하고 마감 전까지 고쳐 냄. 선생님은 제출 현황(미제출·지각 표시), 파일 열기, 점수·피드백 입력, **모두 내려받기(zip, 학번_이름 폴더)**. 피드백은 학생 화면에 보임. 제출 파일은 낸 학생과 담당 선생님만 받을 수 있음 |
| **강의 녹화** | 선생님 화면의 **⏺ 녹화**: 이 수업 화면과 소리(선생님 마이크 + 학생 목소리)를 **선생님 컴퓨터에** 동영상(MP4, 안 되면 WebM)으로 저장. 크롬·엣지는 시작할 때 저장할 곳을 고르고 녹화하는 동안 바로 그 파일에 써서 4시간 수업도 가능(그 밖의 브라우저는 끝날 때 내려받기, 1시간 이내 권장). 서버에는 올라가지 않음. 녹화 중에는 **학생 화면에 '🔴 녹화 중'**, 시작·종료가 채팅과 입·퇴장 기록에 남음. `ALLOW_RECORDING=0` 이면 녹화 버튼이 사라짐 |
| **지난 수업 자료** | 수업 때 띄운 PDF와 판서(화이트보드 포함)가 **수업이 끝나도 남아**, 강좌 수강생(수업을 못 들었어도)과 그 수업에 들어왔던 학생이 첫 화면 '📄 지난 수업 자료'에서 쪽마다 판서와 함께 다시 봄. 선생님은 출결 기록에서 열어 보고 지울 수 있음 |
| 채팅·질문 | 전체 채팅(끄고 켜기), **선생님에게만 보이는 질문**과 1:1 답변, 질문을 공지로 띄우기. **질문답변은 영구 보관**: 선생님은 출결 기록에서 수업별로 조회·CSV, 학생은 첫 화면에서 지난 질문답변 확인 |
| **마이크·카메라 통제** | 기본으로 **학생 마이크는 선생님이 켜고 끔**: 학생은 스스로 켤 수 없고 '🔒 마이크 요청'만 가능(선생님 화면에 🎙️ 표시, ✋ 손 들기와 따로). 선생님이 학생 목록에서 누르면 그 학생 마이크·카메라가 **바로 켜지고**(학생이 누를 필요 없음, 입장할 때 기기 사용만 허용), 다시 누르면 꺼지며 권한도 회수. 권한은 화상 서버가 강제하므로 학생 화면을 고쳐도 우회 불가. 모두 음소거·카메라 끄기, 내보내기(그 수업에 다시 못 들어옴). 통제를 끄면 학생이 자유롭게 켬. 모둠 활동 중에는 자유 |
| **데이터 절약 모드** | 기본으로 켜짐. 전체 교실에서는 학생 카메라 꺼짐(모둠 활동·발언권 때만), 영상 화질 상한. 학생이 받는 데이터가 약 1/3로 줄어 화상 서버 비용과 학생 휴대폰 데이터를 아낌 |
| AI 조교 | 학생 화면 옆에 정치쌤 챗봇. 퀴즈 중에는 선생님이 끌 수 있음 |
| **모둠(소그룹)** | 모둠 수 또는 **모둠당 인원**으로 무작위 배정, 학생마다 모둠 직접 지정, 타이머, 모든 모둠 채팅에 글 공지 |
| **모둠 관찰** | 모든 모둠 영상을 한 화면에, 말하는 모둠 표시. 🎧 원하는 모둠 소리만 골라 듣기(여러 개 동시 가능), 🎤 한 모둠에 들어가 말하기, 🙋 학생 호출 표시 |
| **모든 모둠에 말하기** | 📢 버튼 하나로 모든 모둠에 동시에 선생님 마이크를 켜서 음성 공지 |
| **수업 후 채점** | 출결 기록 화면에서 수업별 퀴즈·활동 답안 확인. 객관식·OX는 자동 채점, 주관식은 점수·피드백 입력, 배점 조정, 학생별 총점, 점수 CSV. **공개**를 켜면 학생이 첫 화면에서 자기 점수·피드백 확인 |
| **출결 기록** | 날짜별 수업 목록 → 학생별 첫 접속·마지막 종료(사유)·접속 시간·**재입장 횟수**·**중간 이탈 시간**, 들어오고 나간 기록 전부. 대상 학급을 정하면 **미접속 학생**도 표시. 출결 요약·입퇴장 전체 기록·퀴즈 결과 CSV(엑셀) |

학생 화면에는 선생님이 그 모둠을 듣고 있을 때 "🎧 선생님이 듣고 있어요"가 표시됩니다. 학생들이 모르게 엿듣지 않도록 일부러 넣은 표시입니다.

### 역할과 승인 흐름

학생의 탈퇴 신청은 소속학교 참여학교 담당교사(없으면 전체 관리자)가 승인합니다. 승인되면 로그인과 일반 수업 API에서 학생의 개인정보·출결·답안·제출물이 제거됩니다. 수업 증빙에 필요한 기록은 암호화된 별도 보관소로 옮기며, 같은 Google 계정의 재로그인은 차단됩니다. 승인된 참여학교 담당교사는 로그인 후 상단의 **탈퇴 학생 증빙** 메뉴(`/live/evidence`)에서 조회 사유를 선택해 담당 학교 기록만 열람하거나 내려받을 수 있습니다. 이메일을 별도로 등록할 필요는 없습니다. 전체 관리자는 모든 학교를 볼 수 있습니다. 목록·열람·다운로드 이력은 기록됩니다.

- 참여학교 담당교사의 승인된 학교 권한을 조회할 때마다 확인합니다. 해당 학교 권한이 회수되거나 기간이 끝나면 증빙 열람도 중단됩니다.
- 참여학교 담당교사가 **내 정보**에서 소속학교를 바꾸고 저장하면 기존 담당 학교 권한은 즉시 중지되고, 전체 관리의 참여학교 담당교사 목록에 **승인 대기** 요청이 자동으로 나타납니다. 전체 관리자가 새 학교를 승인한 뒤에만 그 학교 학생정보·탈퇴 증빙을 볼 수 있습니다. 거절하면 이전 학교 권한도 자동 복구하지 않습니다. 참여학교 담당교사와 거점학교 관리교사의 담당 학교는 각각 한 곳만 허용합니다.
- 탈퇴 증빙은 승인일부터 최대 5년(1,825일) 보존한 뒤 복구할 수 없도록 자동 파기합니다. `EVIDENCE_RETENTION_DAYS`로 더 짧게 정할 수 있고, `EVIDENCE_RETENTION_BASIS`에 운영 기관의 보존 근거를 적습니다. 기존 분리 증빙에도 최대 보존기간을 적용합니다.
- 학생이 서명한 수행평가 점수 확인서 PDF는 강좌 종료일부터 1년(종료일이 없으면 서명일부터 1년)만 보관합니다. 학생이 탈퇴해 분리 증빙으로 옮겨져도 PDF의 1년 만료일에 별도로 파기합니다. 점수·피드백 등 다른 수업 기록은 개인정보 처리방침에 안내한 별도 기간을 따릅니다.
- 증빙·수행평가 점수 확인서 암호화 키는 `EVIDENCE_ENCRYPTION_KEY` 또는 `EVIDENCE_KEY_FILE`로 설정할 수 있습니다. 설정이 없으면 `FILES_DIR/.evidence-key`가 자동 생성됩니다. 배포 서버의 `FILES_DIR`는 지속 저장소여야 합니다. `live-backup`은 데이터베이스만 백업하므로 **암호화 키와 점수 확인서 파일을 별도로 안전하게 백업**해야 합니다. 동일한 키가 없으면 증빙과 점수 확인서를 읽을 수 없습니다. 키를 GitHub에 올리거나 DB 백업에 넣지 마세요.
- 일반 수업 자료의 `RETENTION` 설정과 탈퇴 증빙의 보존기간은 별도입니다. 실제 운영 전 개인정보 처리방침의 보존기간·근거와 백업·다운로드 파일의 파기 절차를 운영 기관에서 검토해야 합니다.

```
전체 관리자 ──승인──▶ 거점학교 관리교사 ──승인──▶ 강사 ──1차 승인──▶ 학생
(ADMIN_EMAILS)                                       └──── 최종 승인 ────┘ (관리교사)
```

| 역할 | 누가 | 할 수 있는 일 |
|---|---|---|
| 전체 관리자 | `ADMIN_EMAILS` 에 적은 계정 | 거점학교 관리교사 신청 승인·거절·해제 (승인하면 그 거점학교가 등록됨). 모든 거점학교의 관리교사 기능도 사용 |
| 거점학교 관리교사 | 관리교사로 신청해 전체 관리자가 승인한 계정 | 자기 거점학교 **강사 등록 승인**(강사가 적은 희망 기간을 보고 활동 기간 확정), 강사가 승인한 학생의 **수강신청 최종 승인**, 거점학교 강좌 현황. 직접 강좌를 열 수도 있음 |
| 강사 | 거점학교를 골라 강사로 신청해 그 학교 관리교사가 승인한 계정 (대학교수, 보충수업 강사 등 소속 무관, 개인 구글 계정 가능) | 그 거점학교에 강좌 개설, 학생 수강신청 **1차 승인**, 수업·출결·채점 |
| 학생 | 학교 구글 계정(`ALLOWED_DOMAINS`) | 어느 거점학교 강좌든 신청 가능(자기 학교가 아니어도). 수강신청 → 강사 승인 → 관리교사 최종 승인 뒤 **수강 확정**, 그때부터 코드 없이 입장. 학번은 학교마다 겹칠 수 있어 여러 학교 학생이 섞인 수업은 출결·채점표에 학교도 표시 |
| 손님 | 그 밖의 구글 계정 | 관리교사·강사 등록 신청만 가능 |

- 학생 수강 상태: **강사 승인 대기 → 관리교사 승인 대기 → 수강 확정** (거절되면 사유가 학생에게 보임). 수강 확정 전에는 강좌 수업에 들어올 수 없습니다.
- 등록 신청에는 이름, 소속(선택), 연락처, **개인정보 보호 서약 동의**가 필요합니다. 강사는 **희망 기간**(시작~끝)도 적습니다(관리교사 승인 화면에 미리 채워짐). 관리교사 신청에는 하고 싶은 말(선택)을 적을 수 있습니다. 한 사람이 여러 거점학교·역할을 가질 수 있습니다(강사 화면의 **다른 거점학교·역할 신청**).
  - 강사였던 사람이 같은 학교 관리교사를 신청하거나, 관리교사가 자기 학교 강사로 등록할 수 있습니다. 두 역할을 함께 가집니다.
  - **본인 신청은 본인이 승인할 수 없습니다.** 관리교사 본인의 강사 신청은 같은 거점학교의 다른 관리교사나 전체 관리자가 승인합니다.
  - 활동 기간이 끝난 뒤 같은 학교에 다시 신청하면 '승인 대기'로 돌아가 관리교사에게 연장 요청으로 보입니다.
- 활동 기간이 끝나거나 권한이 해제되면 **바로 그 기능이 꺼집니다**(수업 기록은 남음). 강사 활동 기간은 끝나는 날을 꼭 정해야 승인됩니다.
- 강사는 **거점학교별로** 권한을 받습니다. 다른 거점학교로 옮겨 예전 학교 기간이 끝나거나 해제되면, 새 학교에서 강사로 활동 중이어도 예전 학교 강좌는 잠깁니다(수강생 관리·수업 열기·지난 수업 기록 열람 불가, 다시 승인받으면 풀림).
- `TEACHER_EMAILS` 에 적은 계정은 신청 없이 강사이며, 거점학교에 속하지 않은 강좌(강사 승인만으로 수강 확정)를 열 수 있습니다.

### 쓰는 법

**학기 초 (한 번)**
0. 관리교사: `https://내주소/live` → 구글 로그인 → **거점학교 관리교사** 신청 → 전체 관리자가 **전체 관리** 탭에서 승인.
   강사: 같은 주소 → **강사** 신청(거점학교 고르기) → 그 학교 관리교사가 **거점학교 관리** 탭에서 승인.
1. 강사: 승인 뒤 다시 들어가면 강사 화면이 열립니다 → **강좌·수강생** 탭에서 강좌를 개설합니다. **강의명·강사명·거점학교명·강의기간**(필수)과 설명(선택)을 적고(거점학교명은 강사 소속과 달라도 되니 직접 입력), 나중에 **정보 수정**으로 고칠 수 있습니다.
2. 학생: 같은 주소 → 학교 구글 계정으로 로그인 → (처음 한 번) 학교·학년·반·번호·이름 → 첫 화면 **수강신청**에서 신청.
3. 강사: **강좌·수강생** 탭 → **수강생 관리**에서 1차 승인(또는 **모두 승인**)·거절. → 관리교사: **거점학교 관리** 탭에서 **최종 승인**(또는 **모두 최종 승인**). 대기 수가 탭에 빨간 숫자로 보입니다.

**수업 때마다**
1. 선생님: **수업** 탭에서 강좌를 고르고 **수업 열기**.
2. 학생: 첫 화면 **지금 들어갈 수 있는 수업**에 수업이 뜨면 **입장하기** (코드 입력 없음, 15초마다 자동으로 새로 고침).
   승인되지 않은 학생은 수업이 보이지 않고, 코드를 알아도 들어올 수 없습니다.
3. 모둠 활동: 오른쪽 **모둠** 탭 → 모둠 수 → **무작위 배정** → **모둠 활동 시작**.
   가운데에 모든 모둠이 보이고, 카드마다 **🔇 듣기 / 🎤 들어가서 말하기**, 위쪽 **📢 모든 모둠에 말하기**.
4. 수업이 끝나면 첫 화면의 **출결 기록** 탭(수업 화면 위 **출결 기록** 버튼)에서 출결·질문답변·채점을 봅니다.

특강·보충수업·상담처럼 강좌와 상관없이 한 번 여는 수업은 강좌 대신 **특강·모임**을 고르면 6자리 수업 코드로 들어옵니다(코드를 아는 학생이면 누구나 입장).
학기가 끝나면 강좌를 **보관**하세요(수강신청이 닫히고 기록은 남습니다).

### 운영 비용

**수업 사이트·화상 서버·데이터베이스를 해외 서버 한 대(Hetzner, 독일·핀란드)에 함께 설치**하는 구성을 권장합니다.
월 정액이라 사용량이 늘어도 요금이 크게 늘지 않습니다.

| 규모 | 서버 | 월 요금 (2026년 6월 가격 인상 반영 추정, 바뀔 수 있음) |
|---|---|---|
| 한두 반 시범 운영 | Hetzner CX23 | 약 €6~7 (약 1만 원) |
| 학교 전체 (교사 50명 × 학생 20명 동시) | Hetzner CX53 (16코어) | 약 €30~37 (약 5~6만 원) |

- 따로 드는 것: AI 조교(Claude API, 쓴 만큼·끄면 0원), 학교 도메인을 쓰면 연 2만 원 안팎(기본 무료 주소는 0원).
- 권장 옵션: Hetzner **Backups**(서버 요금의 20%)를 켜면 서버 전체가 매일 다른 곳에 복사됩니다.
- 1,000명 동시 규모로는 아직 시험하지 않았습니다. 한두 반으로 시작해 늘려 가세요(서버 크기는 콘솔에서 Rescale로 1~2분 만에 올릴 수 있음).

### 설정 순서

**1) 수업 서버 만들기** — **[deploy/server/README.md](deploy/server/README.md)** 를 따라 Hetzner에 서버를 만듭니다.
[`cloud-init.yaml`](deploy/server/cloud-init.yaml) 맨 위 두 줄(전체 관리자 이메일, 학생 계정 도메인)을 채워 붙여 넣으면 설치가 자동으로 끝나고,
`https://class.…sslip.io` 같은 수업 사이트 주소가 생깁니다. HTTPS 인증서·보안 업데이트·재시작·매일 백업이 모두 자동입니다.

**2) 구글 로그인 (Google Cloud 콘솔, 무료)**
1. https://console.cloud.google.com 에서 프로젝트를 만들고 **API 및 서비스 → OAuth 동의 화면**을 설정합니다. 사용자 유형은 **외부**, 범위는 기본(이메일·프로필)만 쓰면 되고, 설정 후 **앱 게시(프로덕션)** 를 누릅니다. 기본 범위만 쓰면 별도 심사가 필요 없습니다.
2. **사용자 인증 정보 → OAuth 클라이언트 ID 만들기 → 웹 애플리케이션**. **승인된 자바스크립트 원본**에 1)에서 받은 수업 사이트 주소(`https://class.…`)를 넣습니다.
3. 서버 콘솔에서 `live-config GOOGLE_CLIENT_ID=만들어진ID` 를 입력합니다.

**3) 학교 구글 관리자에게 앱 허용 요청 (중요)**
Google Workspace for Education은 **만 18세 미만 학생이 관리자가 허용하지 않은 외부 앱에 로그인하는 것을 막습니다.**
학교(또는 교육청) 구글 관리자에게 위 클라이언트 ID를 알려 주고 **관리 콘솔 → 보안 → API 제어 → 앱 액세스 제어**에서
이 앱을 **신뢰함(Trusted)** 으로 설정해 달라고 요청하세요. 이 설정이 없으면 학생은 로그인할 때 "관리자에게 액세스 요청" 화면을 보게 됩니다.

**4) 설정 값** — 서버 콘솔에서 `live-config 이름=값` 으로 바꿉니다(`live-config` 만 입력하면 지금 값이 보임). 수업 사이트가 몇 초 만에 다시 시작됩니다.

| 이름 | 설명 |
|---|---|
| `GOOGLE_CLIENT_ID` | 2)에서 만든 OAuth 클라이언트 ID |
| `ALLOWED_DOMAINS` | 학생 구글 계정 도메인 (예: `s.school.kr`, 쉼표로 여러 개). 비우면 **아무 구글 계정이나** 학생으로 로그인되니 꼭 넣으세요. 다른 학교 학생도 거점학교 강좌를 들으므로 **참여하는 모든 학교의 도메인**을 넣어야 합니다(교육청 공통 도메인이면 하나로 충분) |
| `ADMIN_EMAILS` | **전체 관리자** 이메일 (쉼표로 여러 개, 어떤 구글 계정이든 가능). 거점학교 관리교사를 승인합니다 |
| `TEACHER_EMAILS` | (선택) 신청·승인 없이 바로 강사가 되는 이메일(거점학교 밖 강좌용). 보통은 비워 둡니다 |
| `SCHOOLS` | 학생이 고를 학교 이름 목록 (쉼표). 비우면 직접 입력. 넣는다면 **참여하는 모든 학교**를 넣으세요(목록에 없는 학교 학생은 내 정보를 저장할 수 없음) |
| `ANTHROPIC_API_KEY` | (선택) AI 조교용 Claude API 키. 비우면 AI 조교만 동작하지 않음 |
| `MIC_LOCK` | (선택) `0`이면 새 수업에서 학생이 마이크를 자유롭게 켬. 기본은 선생님이 켜고 끔 |
| `LOW_BANDWIDTH` | (선택) `0`이면 새 수업에서 데이터 절약 모드를 끈 채로 시작 |
| `ALLOW_RECORDING` | (선택) `0`이면 강의 녹화 기능을 끔(학교가 허용하지 않을 때). 기본은 켜짐 |
| `GOOGLE_API_KEY`, `GOOGLE_APP_ID` | (선택) 선생님이 발표 자료를 **구글 드라이브에서 열기**. 아래 '구글 드라이브에서 열기' 참고 |
| `OPERATOR_NAME` | 개인정보 처리방침·이용약관·보호자 안내문에 들어갈 **운영 기관** (예: `가나고등학교`) |
| `PRIVACY_OFFICER` | **개인정보 보호책임자** (예: `교감 홍길동`) |
| `PRIVACY_CONTACT` | 개인정보 문의 연락처 (예: `02-123-4567`) |
| `RETENTION` | (선택) 학생·수업 기록 보유 기간 문구. 기본: `수강한 학년도가 끝난 날부터 5년`. 예전 기본값인 `수강한 학년도가 끝난 날부터 1년`이 설정돼 있어도 5년 문구로 표시합니다. |
| `SERVER_REGION` | (선택) 서버 위치 문구. 기본: `독일 또는 핀란드 (EU)` — 서버를 만든 곳(예: `독일 뉘른베르크`)으로 바꾸세요 |

데이터베이스 주소, 로그인 쿠키 서명 키, 화상 서버 키는 설치 스크립트가 만들어 자동으로 넣습니다.

**(선택) 구글 드라이브에서 열기** — 선생님이 수업 중 '📄 자료 발표 → 📁 구글 드라이브에서 열기'로 드라이브의 PDF·PowerPoint·구글 프레젠테이션을 골라 바로 띄웁니다(PowerPoint·구글 프레젠테이션은 PDF로 바꿔서). 선생님이 **고른 파일 하나만** 여는 권한(`drive.file`)이라 **구글의 별도 앱 검토가 필요 없고**, 모든 과정이 선생님 브라우저 안에서 일어나 서버는 구글 토큰을 받지도 저장하지도 않습니다.
1. 2)의 같은 Google Cloud 프로젝트에서 **API 및 서비스 → 라이브러리**에서 **Google Picker API** 와 **Google Drive API** 를 사용 설정합니다.
2. **사용자 인증 정보 → API 키 만들기** → 키 제한: 애플리케이션 제한 **웹사이트**(`https://class.…/*`), API 제한 **Google Picker API**. 이 키를 `GOOGLE_API_KEY` 에.
3. **Cloud 콘솔 첫 화면(대시보드)의 프로젝트 번호**(숫자)를 `GOOGLE_APP_ID` 에. 예: `live-config GOOGLE_API_KEY=AIza… GOOGLE_APP_ID=123456789012`
4. 학교 워크스페이스 관리자가 외부 앱을 막아 둔 경우, 선생님 계정도 3)처럼 이 앱 허용이 필요할 수 있습니다.

> **다른 방법:** 수업 사이트를 Render(`render.yaml` 의 `live-class`)에, 데이터베이스를 Neon(프랑크푸르트)에 두고 화상 서버만 Hetzner에 둘 수도 있습니다.
> 이때는 위 값과 함께 `DATABASE_URL`, `SECRET_KEY`, `LIVEKIT_URL`·`LIVEKIT_API_KEY`·`LIVEKIT_API_SECRET` 를 Render 환경 변수에 넣어야 하고,
> Render 무료 서버는 잠들 수 있으며 학교 전체 규모에서는 유료(월 $25 정도)가 필요합니다.

### 개인정보 관련 확인할 점

**어디에 무엇이 가나요**

| 서비스 | 위치 | 다루는 정보 |
|---|---|---|
| 수업 서버 (Hetzner) — 수업 사이트·데이터베이스·화상 서버 | **독일 또는 핀란드** | 이메일·이름·학번, 출결, 질문답변, 퀴즈 답·점수·피드백, 매일 백업(14일치), 수업 때 올린 발표 자료와 판서(지난 수업 자료로 보관). 영상·음성은 실시간으로 전달만 함(저장 안 함) |
| AI 조교 (Anthropic) | 미국 | 서버가 식별 가능한 이름·학번·연락처를 가린 질문 내용. 자유롭게 쓴 모든 개인정보를 완벽하게 판별할 수는 없음 |
| 구글 로그인 | — | 학교가 이미 쓰는 구글 계정으로 본인 확인만 함 |

- **이용약관·개인정보 처리방침·보호자 안내문이 들어 있습니다.** 첫 화면 아래 링크(`/live/terms`, `/live/privacy`, `/live/notice`)에서 볼 수 있고, 위 설정 값(운영 기관·보호책임자·연락처·보유 기간)이 자동으로 채워집니다. 처음 로그인할 때 학생·강사가 약관과 처리방침을 확인(동의)해야 쓸 수 있고, 내용을 바꾸면(`app/policy.py` 의 `POLICY_VERSION`) 다음 로그인 때 다시 확인을 받습니다. AI 조교는 처음 쓸 때 "질문이 미국 회사로 전송됨, 개인정보 쓰지 말 것" 안내를 확인받습니다. **보호자 안내문**은 인쇄해 가정통신문(보호자 동의서)으로 쓸 수 있습니다. 모두 초안이니 **학교(교육청) 개인정보 담당자의 검토**를 받은 뒤 쓰세요.
- **해외 이전에 해당합니다.** 한국 밖 서버에 학생 개인정보를 보관·처리하기 때문이에요(개인정보 보호법 제28조의8).
- **EU라면 별도 동의 없이 가능합니다.** 2025년 9월 개인정보보호위원회가 EU 체계를 국내와 실질적으로 동등하다고 인정해서, EU·EEA(독일·핀란드 포함)로는 별도 동의 없이 이전할 수 있어요. 그래서 위 표처럼 사이트·데이터베이스·화상 서버를 모두 EU에 두는 것을 권장합니다. 다만 **개인정보 처리방침(또는 가정통신문)에 이전 국가·항목·업체·보유 기간을 알리는 것**은 필요해요.
- **AI 조교는 미국으로 갑니다.** 학생이 질문에 개인정보를 적으면 미국으로 넘어가요. 학생에게 "AI 조교에 이름·연락처를 적지 말 것"을 안내하거나, 선생님 화면에서 AI 조교를 꺼 두세요.
- **만 14세 미만 학생은 가입할 수 없습니다.** 학생 가입 시 생년월일을 입력받아 서버에서 연령을 확인합니다. 생년월일·성별은 학번과 학교 입력 점검에도 사용합니다.
- **학습지원 소프트웨어 심의:** 교육부가 2025년 12월 발표한 기준에 따라, 정규 수업에서 학생 개인정보를 처리하는 소프트웨어는 필수기준(최소 수집, 안전조치, 열람·정정·삭제 절차, 만 14세 미만 보호, 위탁 등) 체크리스트를 확인하고 **학교운영위원회 심의**를 거쳐야 합니다. 이 플랫폼도 대상이니 학교 담당자와 함께 준비하세요.
- 저장하지 않는 것: 영상·음성 녹화, 전체·모둠 채팅, AI 조교 대화.

### 알아 둘 점

- 수업 도중 `live-update`(새 버전 올리기)는 피하세요. 학생 화면은 자동으로 다시 연결되지만 진행 중이던 채팅·질문 화면이 비워집니다.
- 마이크 통제(기본)와 데이터 절약 모드의 카메라 제한은 화상 서버가 강제합니다. 마이크 통제를 끈 상태에서 '모두 음소거'는 학생이 다시 켤 수 있습니다. 문제 학생은 **✕ 내보내기**로 화상 연결까지 끊을 수 있습니다.
- 출결 기록의 '접속 시간'은 수업 화면을 열어 둔 시간입니다. 화면 앞에 실제로 있었는지는 알 수 없습니다.
- 모둠 관찰 중 여러 모둠 소리를 켜면 섞여 들리니 이어폰을 쓰세요.

### 개발

```bash
pip install -r requirements.txt pytest httpx pyyaml
python -m pytest tests          # 수업 서버 테스트
# 로컬 시험: livekit-server --dev 실행 후 구글 OAuth에 http://localhost:8000 출처를 등록하세요.
GOOGLE_CLIENT_ID=내클라이언트ID.apps.googleusercontent.com ALLOWED_DOMAINS=s.school.kr TEACHER_EMAILS=t@gmail.com \
LIVEKIT_URL=ws://localhost:7880 LIVEKIT_API_KEY=devkey LIVEKIT_API_SECRET=secret \
  uvicorn app.main:app --reload
```

일반 실행에서는 구글 인증을 사용합니다. 자동 테스트에서는 구글 토큰 검증만 모의 처리합니다.

구글 인증 없이 이 컴퓨터에서 계정을 시험하려면 별도 개발용 서버를 실행합니다.

```bash
python -m app.dev
```

터미널에 표시된 `http://127.0.0.1:8000/__dev/login`으로 접속해, 함께 표시되는 **이번 실행의 인증키**와 테스트할 이메일을 입력하세요.
`ADMIN_EMAILS`를 별도로 설정하지 않았다면 `developer@local.test`가 로컬 관리자 테스트 계정입니다.
다른 이메일은 기존 학생·강사·관리자 권한 설정을 그대로 따릅니다.

개발용 서버는 이 컴퓨터에서만 접속할 수 있고, 로컬 SQLite 데이터베이스에서만 실행됩니다.
`DATABASE_URL`이 외부 데이터베이스로 설정되어 있다면 로컬 주소(`sqlite:///./live.db`)로 바꿔 실행하세요.
일반 로그인 화면에는 개발용 버튼이 없으며, 일반 실행(`uvicorn app.main:app`)에는 개발용 로그인 경로도 등록되지 않습니다.
`DEV_LOGIN` 환경변수는 사용하지 않습니다. 인증키는 서버를 다시 실행할 때마다 새로 만들어집니다.

| 파일 | 역할 |
|---|---|
| `app/auth.py` | 구글 로그인, 학교 도메인 확인, 내 정보(학번) |
| `app/classroom.py` | 수업 서버: 입장권 발급, WebSocket 상태 동기화, 퀴즈·모둠·출결 기록 |
| `app/history.py` | 날짜별 수업·출결 조회, CSV |
| `app/db.py` | 데이터베이스 표 정의 (PostgreSQL / 로컬 SQLite) |
| `static/live/` | 첫 화면(`index.html`, `home.js`), 학생(`student.*`), 선생님(`teacher.*`) 화면과 공통 코드 |
| `static/vendor/livekit-client-*.js` | LiveKit 브라우저 SDK (CDN이 막힌 학교망 대비 포함) |
